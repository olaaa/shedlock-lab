## Общее для всех сценариев

- Хранилище блокировок — таблица `shedlock` в PostgreSQL, провайдер `R2dbcLockProvider` с `usingDbTime()`: все сроки считает база. Имя реплики — в `locked_by` (`lab.replica-name`, по умолчанию `replica-<порт>`).
- Журнал запусков — таблица `job_run`: какая реплика, когда начала и закончила. По нему тесты видят дубли и наложения.
- Тестовый контекст — реплика A. Реплика B — второй контекст Spring того же приложения, запущенный из теста, с другим `lab.replica-name` и той же базой в Testcontainers.
- Сроки в тестах — профиль `scenario`, секунды; истечение ждётся через `await`.
- Перед каждым тестом журнал очищается, а блокировки освобождаются `UPDATE`, без удаления строк: строки удалять нельзя (почему — в комментарии к `LockTable.releaseAll`).
- Весь набор, 8 тестов, прогнан четыре раза подряд без падений; прогон — около 70 секунд, из них 35 — тест продления.
