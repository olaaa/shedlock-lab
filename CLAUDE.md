# shedlock-lab — правила для ассистента

- Публичный репозиторий. Никаких корпоративных имён: сервисов, таблиц, пакетов, тикетов и названий компаний из рабочих проектов. Список запрещённых слов лежит в `.git/info/forbidden-words` и проверяется хуками `pre-commit` и `commit-msg`.
- Тема: ShedLock — блокировка для задач по расписанию, чтобы задачу выполняла одна реплика. Продолжение сценария 3 в [redis-patterns-lab](https://github.com/olaaa/redis-patterns-lab) (блокировка с арендой, собранная вручную на Redis): здесь — готовая библиотека и хранилище PostgreSQL.
- Стек: Java 25, Spring Boot 4.1, WebFlux, R2DBC через `DatabaseClient`, Reactor, ShedLock 7 (`shedlock-spring`, `shedlock-provider-r2dbc`). Без JPA.
- Каждый приём — отдельный компонент и отдельный тест `ScenarioN…Test`. У каждого сценария — описание в `docs/scenarios/NN-….md` и файл ручной проверки `http/NN-….http`; при изменении сценария обновлять все три.
- Тесты поднимают PostgreSQL в Testcontainers. Тестовый контекст — реплика A, вторая реплика — отдельный контекст Spring того же приложения с другим `lab.replica-name`. Сроки — из профиля `scenario` (`src/test/resources/application-scenario.yml`). Время блокировок считает база (`usingDbTime()`), поэтому сроки в тестах настоящие, секунды; ждать через `await`, без `sleep`.
- Задачи под `@SchedulerLock` — блокирующие методы: ShedLock держит блокировку, пока метод не вернул управление. Метод, возвращающий `Mono`, не защищён (тест `methodReturningMonoIsNotProtected`).
- Цитаты в описаниях — на русском, в переводе; названия статей и разделов можно оставлять как есть.
- Стиль: многострочные комментарии одним блоком `/* */`, фигурные скобки у тел `if`/`for`/`while`, говорящие имена.
- Ветка `main`. Коммит и пуш — по окончании задачи, `git add` по именам файлов, перед пушем `git fetch`.
